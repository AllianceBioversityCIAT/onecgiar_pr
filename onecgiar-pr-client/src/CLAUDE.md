# CLAUDE.md — `onecgiar-pr-client/src` (source-tree navigation & patterns)

This is the **source-tree guide** for the PRMS Angular client. It complements the package-level [`../CLAUDE.md`](../CLAUDE.md), the root [`../../CLAUDE.md`](../../CLAUDE.md), and the SDD baseline under [`../../docs/`](../../docs/).

> **Read order:** root → package → this file. Everything below assumes you already know the SDD methodology and the high-level architecture (**Angular 21 + Tailwind CSS 4 + Spartan UI**, custom `auth` header, no NgRx). **PrimeNG is gone** — not a dependency, 0 `primeng` imports under `src/`; only the `primeicons` stylesheet remains.

> **Document-as-you-go (keep this file current).** Whenever you investigate a feature/flow to do a ticket, append the non-obvious wiring you discovered here — where a field/section lives, which service/DOM mechanism drives it, the gotchas. Keep entries **short** (a couple of lines, not essays) and token-cheap: a pointer + one sentence beats a wall of text. This file is the shared map; growing it once saves re-investigation on every future ticket.

## 1. Bootstrap & wiring — rules only

- `main.ts`: no side effects. Global one-time setup belongs in `app.module.ts` via `provideAppInitializer`.
- `styles.scss`: use the `.completeness-*` / `.result-list-state` pills for `status_id` chips so the workflow colour mapping stays consistent. `.globalDisabled` is visual-only — always pair it with the real `disabled` attribute. `body.pr-p25-drawer-scroll-lock` belongs to the P25 column drawer — don't repurpose it. Don't add new ad-hoc utility families to `styles.scss`; use `src/styles/<topic>.scss`.

## 2. `app/` — rules only

- Don't add app-wide providers to `app.module.ts` without a spec. Page-specific providers belong in the feature module.
- No feature logic in `app.component` — extract into `shared/components/`.
- Theming is pure CSS (no `providePrimeNG`, no TS preset) — see §13.

## 3. `app/pages/` — Top-level surfaces

### 3.1 Standard feature module layout

```
pages/<feature>/
├── <feature>.module.ts
├── <feature>-routing.module.ts
├── <feature>.component.{ts,html,scss,spec.ts}
├── <feature>.service.ts            # Optional, feature-level state/state-orchestration
├── (optional) <feature>.responsive.scss  # Feature-level responsive overrides
├── components/                     # Feature-only components (subfolder per component)
├── pages/                          # Nested routed sub-pages (mirrors this same shape)
└── services/                       # Feature-local services
```

Modules (`.module.ts`) are excluded from coverage. Routing modules (`*-routing.module.ts`) are excluded from coverage.

### 3.2–3.3 Page and result-detail gotchas

- `pdf-reports/` is mounted under TWO paths (`/reports/result-details/:id` and `/reports/ipsr-details/:id`) on purpose.
- `result-creator.responsive.scss` is the canonical pattern for feature-level responsive styling — mirror it for heavy form flows.
- Type-specific result-detail sub-pages (`rd-result-types-pages/`) are selected by the numeric `prHide` = server `ResultTypeEnum` value. A new server result type needs a new sub-page AND a `prHide` entry in `routing-data.ts → rdResultTypesPages`.
- `rd-theory-of-change`, `rd-partners`, `rd-links-to-results` are P22 only; `rd-contributors-and-partners` is P25 only and excluded from coverage.
- `requests/received` rows open a right-side drawer (`components/contribution-request-drawer/`) alongside the row's original popup flow — both live, never together (CRD-DD-10). See that folder's `CLAUDE.md` and the sibling `notification-item/CLAUDE.md`.

### 3.4 Adding a new feature module under `pages/`

1. Create `pages/<feature>/` with the standard layout (§3.1).
2. Register the route in `app/shared/routing/routing-data.ts`:
   - Top-level → add to `routingApp` (or `extraRoutingApp` if admin-gated).
   - Sub-route → add to the appropriate nested table (`resultRouting`, `adminModuleRouting`, `notificationsRouting`, etc.).
   - Use `PrRoute` (the project's `Route` extension) so `prName`, `prHide`, `underConstruction`, `onlyTest`, `portfolioAcronym` are available.
3. Apply guards: `CheckLoginGuard` for authenticated routes, `CheckAdminGuard` for admin-only.
4. Lazy-load via `loadChildren` (preferred for full feature modules) or `loadComponent` (for single-page features).
5. Import only the primitives the feature needs into the new `.module.ts` (`CustomFieldsModule`, the specific Helm imports). Don't barrel-import a whole UI library.
6. If the feature has multi-section editing, model it as a `panel-menu` + nested `pages/`. Don't reinvent navigation.

## 4. `app/shared/routing/`

Single file: `routing-data.ts`. Exports many `PrRoute[]` tables consumed by feature `*-routing.module.ts` files.

### 4.1 `PrRoute` extension

```ts
export interface PrRoute extends Route {
  prName: string;                 // Display label for nav / breadcrumbs / panel-menu
  prHide?: boolean | number;      // true → hide; number → tie route to a result_type_id
  underConstruction?: boolean | number;
  onlyTest?: boolean;             // Limit to test env
  portfolioAcronym?: string;      // 'P22' | 'P25' — controls portfolio-version visibility
}
```

The number form of `prHide` is **load-bearing for result-detail navigation** (it maps to `ResultTypeEnum`). Don't strip it.

### 4.2 Route tables — rules

- Misspelled table names are intentional — don't rename: `managementPhasesRuting`, `TypePneReportRouting`.
- When adding/removing a route, update `routing-data.ts`. The panel-menu, breadcrumbs, and nav-bar all read `prName`, so a typo there shows up in the UI.

## 5. `app/shared/services/`

Two layers: **API services** (HTTP) under `services/api/` and **state/orchestration services** at the top.

### 5.4 Service rules

- **One service per concern.** If the file is creeping past ~400 lines, split it.
- **State → signals first, RxJS where needed.** Components SHOULD bind to `*Signal` properties; legacy `BehaviorSubject` fields are being migrated.
- **Service methods are idempotent unless they explicitly mutate.** Pure reads should not push to UI state as a side effect.
- **`HTTP_METHOD_descriptiveName`** naming — apply to every HTTP method you add.
- Most components inject `ApiService` (the aggregator) once and reach feature services through it.
- New cross-feature flags go in `data-control.service.ts` — don't sprinkle them in components (its `chagePhaseModal` is a load-bearing typo).
- Use `logger.service.ts` instead of `console.log` for anything that should reach telemetry.
- `customized-alerts-fe` (banners) vs `customized-alerts-fs` (full-screen dialogs) — pick the right one per scenario.
- `variables/pusher-blocked-routes.ts` lists routes where Pusher must NOT fire.
- `services/global/` catalog services are read-mostly in-memory caches — keep them lightweight.
- ⚠️ `global/centers.service.ts` is fetched **once** at bootstrap. P2-3554: the request retries (`retry` + `defer`, each attempt re-issues it) and treats a 200-with-empty-list as a failed attempt; `getData()` is idempotent once loaded, so a screen that needs the list may call it again to recover. Before that, one bad response emptied **every** centres dropdown app-wide until a reload.

## 6. `app/shared/interceptors/` — `GeneralInterceptorService`

`general-interceptor.service.ts` is the project's only HTTP interceptor. Its responsibilities:

1. **Attach `auth` header** with `localStorageToken` to every request — except requests whose URL contains `environment.elastic.baseUrl` (the client hits Elasticsearch directly with separate credentials).
2. **Side effects on success of `PATCH` / `POST`:**
   - If the current router URL contains `/result/result-detail/` → call `GreenChecksService.getGreenChecks()`.
   - If the request URL contains `/api/ipsr/` AND is not in the small denylist (`['/api/ipsr/all-innovations']`) → call `IpsrCompletenessStatusService.updateGreenChecks()`.
3. **Errors** bubble through `manageError` for caller-side handling. No automatic toast — components / services are responsible for surfacing errors.

**Rule:** If a new flow shouldn't trigger the completeness refresh, add its URL to the `notValidateList` inside the interceptor — **do not bypass the interceptor**.

|---|---|---|
| `CheckLoginGuard` | If `authService.localStorageToken` exists → allow; else redirect to `/login`. | `routingApp` (most top-level routes). |

## 8. `app/shared/components/`

Reusable UI primitives. **Each component lives in its own folder** with the canonical 4-file layout (`.ts`, `.html`, `.scss`, `.spec.ts`). Add a `<name>.module.ts` next to them when the component declares its own NgModule (most do, to remain consumable as an `imports:` target).

- `page-header/` — every page should use it.
- `steper-navigation/` (sic) — don't rename the typo.

### 8.1 Adding a new shared component

1. `app/shared/components/<name>/` with the 4-file layout.
2. Add a `<name>.module.ts` that imports the primitives this component uses (`CustomFieldsModule`, the specific Helm imports), declares the component, and exports it. This makes it consumable via `imports: [...]` without scattering UI-library imports across features.
3. If the component takes more than 5 inputs, document them at the top of the `.ts` file (multi-line comment is fine).
4. Style with `--pr-*` tokens. **Never hardcode hex.**
5. Strings via `internationalization/` — see §11.

## 11. `app/internationalization/` — Terminology service

The PRMS i18n is **portfolio-driven**, not locale-driven:

```ts
@Injectable({ providedIn: 'root' })
export class TerminologyService {
  t(key: TermKey, portfolioAcronym: string): string {
    const dict = portfolioAcronym === 'P25' ? NEW_TERMS : LEGACY_TERMS;
    return dict[key] ?? key;
  }
}
```

Dictionaries `LEGACY_TERMS` and `NEW_TERMS` are defined in `terminology.config.ts`. Static seed data lives in `app/shared/data/internationalization-data.ts`.

### Rules

- All user-facing copy that differs between **P22 and P25** MUST be authored as a `TermKey` and consumed via the pipe `term`.
- Locale (English / Spanish / etc.) is **not** in scope today — the keys are ready for future locale extension but the service only switches portfolios.
- Hardcoded English IS acceptable for purely structural / non-domain copy (`"Cancel"`, `"OK"`) — but consider promoting to `TermKey` if it's recurring.

## 13. Theming — CSS tokens only (there is no `app/theme/`)

⚠️ **`app/theme/reportingTheme.ts` does not exist.** The PrimeNG theme preset was deleted with PrimeNG itself (commit `50710ea38`) and the `app/theme/` folder is gone. Any instruction to "mirror the SCSS in the TS theme" is stale — **delete the thought, there is nothing to mirror.**

What replaced it:

- `styles/colors.scss` + `styles/fonts.scss` — the only source of truth for values (`--pr-*`).
- `styles.scss` — an `@theme inline { … }` block that re-exposes those vars to Tailwind (`--color-brand-*`, `--color-surface-*`, `--color-ink-*`, `--font-mono`) and maps the Helm/shadcn keys (`--background`, `--primary`, `--ring`, `--sidebar*`) onto `--pr-*`. `inline` is required: the values are `var()` references, so a plain `@theme` would freeze resolution at `:root` and break scoped overrides.
- **Don't redeclare a key the Helm preset already owns** (`--color-sidebar`, `--color-sidebar-foreground`): that severs `bg-sidebar` from the raw `--sidebar` var, which is the mechanism that paints the sidebar dark on a light page. Set the *value* on the raw var instead.

Dark mode is **not** supported: `color-scheme: light` is pinned on `:root` and the unreachable `:root.dark` block was removed (see the note in `styles.scss`).

## 18. `environments/`

### Important rules

- **Elasticsearch credentials are checked in here** in plaintext (`elastic.username`, `elastic.password`). They belong to the test cluster only. **Never put production credentials in either environment file.** Production ES auth flows through API Gateway and per-environment secrets.
- `apiBaseUrl` is the **single source** of API base; everything else (`baseApiBaseUrl`, `apiBaseUrlV2`, etc.) is composed in services from this value.
- Closure flags (`resultModuleIsClosed`, `IPSRModuleIsClosed`, `platformIsClosed`, `platformInQA`) gate whole surfaces — flipping them affects the UI globally.
- Don't introduce new top-level env keys without updating both `environment.ts` AND `environment.prod.ts`.

## 19. `styles/` — Global SCSS tokens

### Rules

- **SCSS is the single source of truth.** `styles/colors.scss` / `fonts.scss` hold the values; `styles.scss` only references them with `var()`. There is **no TS theme to mirror** (see §13).
- Prefix every PRMS variable / class with `--pr-` / `.pr-`. Don't collide with the Helm preset's keys (`--primary`, `--ring`, `--color-sidebar`, … from `@spartan-ng/brain/hlm-tailwind-preset.css`).
- A deliberate departure from the visual reference goes in `../docs/DESIGN-DEVIATIONS.md` **with the measurement that justifies it** — that file exists so nobody "corrects" an accessibility fix back to the mockup value.
- Tables use `table-custom-styles.scss`; filter strips use `filters-list.scss`; alerts use `custom-alert.scss`.
- Don't introduce hex literals in feature SCSS. If a token is missing, add it to `colors.scss` first.
- The result-level palette `--pr-color-result-level-1..4` is semantic — do not reuse it for anything else.
- `.pr-code` / `.pr-figure` / `.pr-figure-sm` carry `font-variant-numeric: tabular-nums` — dropping it breaks figure-column alignment.
- Poppins survives only as a fallback alias in the font stack (not loaded, not the brand face). Instrument Sans and Inter were deliberately not adopted.

## 21. Patterns to follow

### 21.1 Service shape

```ts
@Injectable({ providedIn: 'root' })
export class FooService {
  private readonly api = inject(ResultsApiService);
  readonly fooSignal: WritableSignal<Foo | null> = signal(null);

  loadFoo(id: number) {
    this.api.GET_fooById(id).subscribe(({ response }) => this.fooSignal.set(response));
  }
}
```

- `@Injectable({ providedIn: 'root' })` for shared services.
- Prefer `inject()` over constructor params for new code; preserve existing constructor injection where present.
- State on `WritableSignal<T>` for new code.
- Destructure `response` from the standard envelope.

### 21.2 Component shape

```ts
@Component({
  selector: 'app-foo',
  templateUrl: './foo.component.html',
  styleUrls: ['./foo.component.scss']
})
export class FooComponent {
  private readonly api = inject(ApiService);
  readonly fooSignal = computed(() => this.api.dataControlSE.currentResultSignal());
}
```

- Reach feature services through `ApiService` (the aggregator) — `this.api.dataControlSE`, `this.api.resultsSE`, etc.
- Templates bind to signals: `{{ fooSignal() }}`.
- Forms via `pr-input` / `pr-select` (from `custom-fields/`) or a Spartan/Helm control — never a bare native input.
- No inline `style="..."`. Use `--pr-*` classes or component SCSS.

### 21.3 HTTP service methods

```ts
GET_resultById(id: number) {
  return this.http.get<ReportingApiResponse<CurrentResult>>(`${environment.apiBaseUrl}api/results/${id}`);
}
```

- Name as `HTTP_METHOD_descriptiveName`.
- Use the right base URL (see [`../CLAUDE.md`](../CLAUDE.md) §2). The interceptor will attach the `auth` header.
- Type the response. Don't return `any`.

### 21.4 Side effects

- The interceptor handles green-checks and IPSR completeness refresh post-PATCH/POST. Add new exclusions to `notValidateList` inside the interceptor; don't bypass it.
- Real-time events (sockets, Pusher) are **hints** — always reconcile via API before mutating UI state.

### 21.5 Forms & validation

There are **two independent layers** — don't conflate them:

1. **Field-level mandatory feedback (frontend, client-side).** Result Detail's parent (`result-detail.component.ts`) calls `DataControlService.someMandatoryFieldIncompleteResultDetail('.section_container')`, which **scans the section DOM** for `.pr-field.mandatory` elements without a `.complete` class (and `.pr-input.mandatory .input-validation`), and builds `fieldFeedbackList` for the validation alert. Two things emit a scannable `.pr-field.mandatory`:
   - the **`appFeedbackValidation` directive** (`shared/directives/feedback-validation.directive.ts`) — a hidden `<div appFeedbackValidation labelText="…" [isComplete]="…">` that toggles `.complete`; use this when the control is a raw widget that emits no `.pr-field` wrapper of its own (e.g. a bare Helm select).
   - **`app-pr-select [required]`** (`custom-fields/pr-select`) — its root is `<div class="pr-field" [ngClass]="{ mandatory: required, complete: <has value> }">`, so a required `app-pr-select` is scanned automatically. A bare Helm/native select is **not** — flipping `app-pr-field-header [required]` only adds the asterisk.
2. **Section green check (BACKEND).** The gray/green section indicator comes from `green_checks` fetched by `green-checks.service.ts` (`GET_greenChecksByResultId` / `GET_p25GreenChecksByResultId`), refreshed by the interceptor on PATCH/POST. The frontend only renders it — to make a field affect the green check, the **server** completeness query must include it.
- Programmatic labels: every form control has a `for=` label or an `aria-label`.

3. **The requiredness MARKER is a third, purely visual layer — it is not what the scan reads.** Migrated field types (`pr-input`, `pr-textarea`, `pr-radio-button`, `lead-contact-person-field`, and the P25 Impact-Area checkbox groups) render through **`app-field-card`**, which shows a `Mandatory` / `Optional` pill plus a state-coloured border (`fc-optional` blue / `fc-pending` orange / `fc-done` green / `fc-error` red). Non-migrated types (`pr-select`, `pr-multi-select`, `pr-yes-or-not`, `pr-checkbox`, `pr-range-level`) still render `app-pr-field-header`, whose red asterisk comes from `.required::after` in `pr-field-header.component.scss`. The two never coexist on one field, and **neither one is read by `someMandatoryFieldIncompleteResultDetail`** — the scan only reads the `mandatory` / `complete` classes on the control. That is why `pr-multi-select`, `pr-yes-or-not`, `pr-checkbox` and `pr-range-level` can show a marker while contributing nothing to the alert count. Corollaries:
   - `app-field-card` renders **no chrome at all** when it has neither a label nor a description (`isBare`) — this preserves the pre-redesign behaviour of `app-pr-field-header`'s `*ngIf="this.label"` for the ~60 label-less call sites (currency cells, sub-inputs, "Other" specifiers) that would otherwise grow an orphan "Mandatory" pill.
   - A card's `hasValue` must be bound to the **same expression** as the control's `complete` class, or the colour and the alert list disagree on edge cases (`''`, whitespace-only). `pr-input` may trim because its scan reads `.input-validation` innerText; `pr-textarea` and `pr-radio-button` may not.
   - `app-field-card` is in `LABELLED_FIELD_HOSTS`, so a migrated field must keep its label inside `.fch_title` or `mandatoryFieldLabel` falls through to a bounded ancestor `querySelector` that can pick up a neighbour's label.

4. **Per-section loading skeleton.** Result Detail sections mark their root `<div class="detail_container">` with **`[appSectionSkeleton]="sectionLoading()"`** (`custom-fields/section-skeleton/`). The directive adds `.rd-loading` + `aria-busy` + `inert`; the global mask in `custom-fields/section-skeleton/section-skeleton.scss` paints the `.pr-input` / `.pr-field` / `.custom_select` / `.choices` / `.checkbox_container` / `.prl` bodies with the `.pr-skeleton` grey and neutralises the `fc-*` colours. It masks the **live DOM** — never an `@if` — precisely because layer 1 above scans that DOM. Convention: `sectionLoading = signal(true)` initialised at construction (three sections load from an `effect()`, so "a request is in flight" is not a usable signal) and released in **both** the `next` and `error` handlers of the GET that fills the body. It replaced the dark `.spinner` veil in `result-detail.component.html`; `SaveButtonService.isGettingSection` / `isGettingSectionPipe()` remain because IPSR still renders the veil from them.

### 21.7 Modals

- Reuse `share-request-modal`, `change-phase-modal`, etc. Don't reinvent.
- New global modals → `shared/modals/<name>/`, imported in `app.module.ts`, triggered via a flag on `DataControlService`.
- ⚠️ **`app-pr-dialog` has no focus trap, no autofocus and no focus restore** (verified: `grep cdkTrapFocus|FocusTrap|autoFocus|restoreFocus` over `shared/components/pr-dialog/pr-dialog.component.*` finds nothing). Fine for a click-driven confirm; **not** fine for anything keyboard-driven. Its docstring's claim that it exists to avoid `hlm-dialog` "which drags in @ng-icons" is stale — @ng-icons is a direct dependency. For a keyboard-first overlay use Spartan `hlm-dialog` (CDK Dialog: `autoFocus`, `restoreFocus`, trap) — see `shared/components/global-search-palette/`.
- Global search palette lives at `shared/components/global-search-palette/` and is mounted by `shell-topbar`; the topbar Search control is a **trigger button**, no longer a filter input, and no longer touches `ResultsListFilterService`. Both folders have their own `CLAUDE.md`.
- ⚠️ `GET /api/results/get/all/roles/filter/:userId` answers **404 `Results Not Found`** when a filter matches nothing, not 200 with an empty list. Any new caller must treat 404 as "empty", not as a failure.
- ⚠️ Generated Helm classes are **concatenated, not `tailwind-merge`d**, onto whatever `class` you pass — so a Helm `max-w-*` (e.g. `hlm-dialog-content`'s `sm:max-w-md`) silently beats your `w-[...]`. Override the same utility explicitly, with `!` if needed.
- ⚠️ `ng g @spartan-ng/cli:info --json` misreports `installedComponents`. **Trust `ls src/app/spartan/`.**
- ⚠️ `npx tsc --noEmit` does **not** typecheck Angular templates — only `npm run build` does. A template calling `String(...)` (no such global in a template) passes `tsc` and fails the build.

## 22. Anti-patterns to avoid

- **Hardcoded English in templates** — use the `term` pipe and dictionaries.
- **Inline `style="margin: 12px"`** — use `.m-12`, `.mb-12`, etc. from `styles.scss`.
- **Hex literals in SCSS** — extend `colors.scss` first, then consume `var(--pr-color-*)`.
- **Bypassing `GeneralInterceptorService`** — even Elasticsearch is opt-out *inside* the interceptor.
- **Per-feature soft-delete / green-checks logic** — centralize in `data-control.service.ts` and `green-checks.service.ts`.
- **Renaming the misspellings** (`steper-navigation`, `TypePneReportRouting`, `managementPhasesRuting`, `chagePhaseModal`, `typeOneResportEmbedded`) — they're in code paths and config keys consumed elsewhere.
- **Adding new top-level folders under `app/`** — extend `shared/` instead.
- **Barrel-importing a whole UI library in `app.module.ts`** — per-feature module imports keep the bundle reasonable.
- **Reintroducing `primeng` or a TS theme preset** — PrimeNG was removed on purpose (0 imports; only `primeicons` CSS) and `app/theme/` no longer exists.
- **Editing a file in a folder that has its own `CLAUDE.md` without updating that `CLAUDE.md` and re-stamping its `Verified:` line in the SAME commit** — convention and template in `../docs/COMPONENT-DOCS.md`.
- **Re-enabling `WebsocketService` silently** — it's commented out for a reason; coordinate with the server team.
- **Hiding admin UI without a guard** — `CheckAdminGuard` is the enforcement point.
- **Pushing production secrets into `environment.prod.ts`** — keys here are checked in.
- **Bypassing `ResponseInterceptor` envelope** — destructure `response`, don't read the whole body.

## 25. SDD workflow (inside `src/`)

When you sit down to edit anything in this tree:

1. Confirm the spec at `../../docs/specs/<module>/` (`requirements.md`, `design.md`, `task.md`). If missing, run `/sdd-specify` first — templates live in `../../docs/specs/general-setup/`.
2. Cite `G#`, `US-*`, `AC-*` from `../../docs/prd.md` and the screen / flow / component rule from `../../docs/ux-ui/design.md`.
3. Implement using the folder patterns in §3 / §8 / §9 / §10 / §14, the service shape in §21, and the interceptor / guard / theme rules in §6–7 / §13 / §19.
4. Update typed interfaces under `app/shared/interfaces/` if API contracts changed.
5. Tests co-located. Don't lower coverage (client thresholds 50/60/60/60).
6. **Verify in the browser.** UI changes are not "done" because the build passes — run `npm start` and exercise the flow.
7. If you introduced a new UX pattern that should be reused, promote it to `../../docs/ux-ui/design.md` (§12 Design Decisions).
8. Commit using the project's `<emoji> <type>(<scope>) [ticket]: <description>` convention.
