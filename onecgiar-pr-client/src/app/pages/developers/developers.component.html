Developers

Send W3 results to PRMS directly from your own platform, in a standard format, individually or in bulk, instead of reporting them by hand.

How to integrate

Five steps from nothing to results landing in PRMS.

  1. 1

    Request your test API key

    Ask for a key for the test environment first. Your key identifies your platform on every call.

  2. 2

    Read the field documentation

    Check which fields your result type needs and which values PRMS matches against the CLARISA catalogues.

  3. 3

    Send a result to the test environment

    Post one result to single result ingest and confirm the response. Add your own external_reference so you can match the response to your record.

  4. 4

    Register a webhook

    Point PRMS at an HTTPS endpoint of yours to find out when a Science Program approves or rejects a result. Optional, but decisions taken before you register are not sent again.

  5. 5

    Request your production key and switch

    Same payload, different key and different URLs. Never reuse the test key in production.

Get an API key

Every call needs a CLARISA API key in the x-api-key header. There is no anonymous access. Keys are issued by the PRMS team, one per platform and per environment: never reuse a key across tools or between test and production, because the key is what identifies your platform to PRMS.

Result decision webhooks

Register an HTTPS callback with your API key and PRMS will notify you when a Science Program approves or rejects one of your results, with the reviewer's justification. Register it before your results go under review: decisions taken with no destination registered are not sent again.

What you still do in PRMS

Two things the API cannot carry:

  • Confidential evidence. The API accepts public links only. Evidence that cannot be public is uploaded in the reporting tool.
  • Fields beyond the minimum data standards. Send keep_editing as true and the result arrives as Editing, so the reporting user completes it and submits it from PRMS.
Questions about the API? Contact the PRMS technical team.
