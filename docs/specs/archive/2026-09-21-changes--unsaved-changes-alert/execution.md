### Post-hoc fix — `UCA-T-3` build defect (`unsaved-changes-dialog.component.ts`)

- **Status:** FIXED (Leader-verified, no separate Reviewer cycle — single type-annotation change, mechanical)
- **Date:** 2026-09-10
- **Discovered by:** `UCA-T-6`'s Implementer, running `npm run build` as part of its own verification, surfaced a pre-existing `TS2345` in `UCA-T-3`'s file that had not been caught during `UCA-T-3`'s own review.
- **Root cause:** `@HostListener('keydown.escape', ['$event'])` is a TypeScript decorator, not a template binding — Angular's template type-checker only infers event types (`keydown.escape` → `KeyboardEvent`) inside `(event)="handler($event)"` template syntax. A decorator string is just metadata to TypeScript, so `$event`'s real inferred type is `Event`, not `KeyboardEvent`. The handler only calls `event.preventDefault()`, so no `KeyboardEvent`-specific behavior was ever needed.
- **Fix:** `onEscape(event: KeyboardEvent)` → `onEscape(event: Event)`. One line, `onecgiar-pr-client/src/app/shared/components/unsaved-changes-dialog/unsaved-changes-dialog.component.ts:55`. No logic change.
- **Verification:** `npx ng lint --quiet` clean; `npm run build` — the TS2345 for this file is gone, only the already-known-and-accepted pre-existing TS2341 (bilateral tree, `bbe95dbf9`) remains; `npm run test -- --testPathPattern="unsaved-changes-dialog"` → 2 suites / 8 tests still green (Escape-resolves-as-discard test unaffected, confirming the type-only change is behavior-preserving).
