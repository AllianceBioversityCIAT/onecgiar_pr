# Design — Other(s) Contributing Centers/Science Programs shown by default (P2-3499)

**Depth:** Lite (Bug Mode). Not architecturally significant — no new module, no persistence/API change, no NFR-scenario impact. `software-architect` Decision Spine not invoked. No new visual design needed (relabel + branch-copy of existing, already-styled components) — `ui-ux-pro-max`/`frontend-design` not invoked.

Linked: `docs/specs/bugfix/other-fields-toc-visibility/requirements.md` (`OTV-R-1..6`, `OTV-AC-1..7`).

## 1. Summary

**Revision note (post-Judgment Day round 1, see `judgment.md`):** the original plan ("change a static `label=` string") was not implementable as written — the empty-ToC dropdown and the opt-in "Other(s)" dropdown are **the same DOM element** in `rd-contributors-and-partners` and `aow-hlo-create-modal`'s Centers case, so a static relabel would have also relabeled the genuine opt-in case (breaking `OTV-AC-7`), and would have left a pre-existing field-header duplicated on screen. The plan below replaces the static label/new-header approach with a **conditional label** (Centers, both components) and a **conditionally-rendered header** (aow's Science case, which is a `app-pr-field-header` + `app-pr-filter-multiselect`, not a labeled multi-select). `lab-report-form` never had a `label` at all (only a `placeholder`) — that stays true; only its `placeholder` becomes conditional, per Judge B's finding that adding `label=` there would reverse a documented convention.

- **Centers, both `rd-contributors-and-partners` and `aow-hlo-create-modal`:** the auto-activated dropdown's `label` becomes `[label]="hasReferenceCenters() ? 'Other(s) Contributing CGIAR Centers' : 'Contributing CGIAR Centers'"` — i.e. it keeps saying "Other(s)…" when the user genuinely opted in after the ToC found centers, and drops the "Other(s)" framing only in the true empty-ToC auto-activated case. The redundant field-header already rendered in the "no centers found" `@else` branch is removed (it would otherwise duplicate the label now carried by the dropdown itself).
- **Science, `rd-contributors-and-partners`:** identical conditional-label + redundant-header-removal pattern, mirroring Centers.
- **Science, `aow-hlo-create-modal`:** the "Other(s)…" text lives on a **separate `app-pr-field-header`**, not a multi-select `label` — so instead of a conditional label, that field-header is wrapped in `@if (hasReferenceScience())` and only renders (with "Other(s)…" text) in the genuine opt-in case. In the auto-activated empty-ToC case it renders nothing extra — the section's own top-level "Contributing Science Programs/Accelerators" header plus the orange note already identify the control, so no duplicate and no "Other(s)" framing.
- **`lab-report-form`:** add the missing `hasReferenceCenters()`/`hasReferenceScience()` computeds and the `@if/@else` branch (note in the empty case), reusing the four info-note/copy constants that **already exist** in this file (`contributingCentersInfoNote`, `noCentersNote`, `contributingScienceInfoNote`, `noScienceProgramsNote` — no new constants needed). The auto-activated dropdown gets **no new `label`** (this component deliberately renders no label chrome on its multi-selects, per its own `CLAUDE.md`); instead its `placeholder` becomes conditional: `[placeholder]="hasReferenceCenters() ? 'Other CGIAR Centers' : 'Select center(s)'"` (Science equivalent), so the placeholder itself drops the "Other" framing in the empty-ToC case, matching the component's existing no-label convention.
- Shape of the solution: template-only conditional-rendering + string changes, driven by the `hasReferenceCenters()` / `hasReferenceScience()` computeds that already exist (two of three components) or get added (the third). No service, entity, or API change.
- Biggest constraint: three near-duplicate components must be edited consistently without merging them (merging is out of scope, per requirements §3) — so the design is "apply the same small patch three times," not "refactor to one source," and each of the three needs a *slightly different* mechanism because their existing markup differs (labeled multi-select vs. field-header + unlabeled multi-select vs. label-less multi-select with placeholder only).

### 2.2 Interaction (per component, same shape)

```
[Template renders section]
  └── hasReferenceCenters() / hasReferenceScience()  (existing computed; ADDED in lab-report-form)
        ├── true  → UNCHANGED: primary dropdown/entity-picker shows ToC-found items + "Other(s)" sentinel;
        │           second dropdown/header appears only if the user selects the sentinel
        │           (showOtherCenters()/showOtherScience()) — and when it does, it STILL reads "Other(s)…"
        │           (conditional label/header keeps the old text for this genuine opt-in case)
        └── false → orange note (unchanged copy), NO redundant duplicate header, and the auto-activated
                     full-catalog dropdown/entity-picker WITHOUT "Other(s)…" framing:
                       - rd-contributors-and-partners / aow Centers: [label] conditionally resolves to the
                         primary field's own label instead of "Other(s)…"
                       - aow Science: the "Other(s)…" field-header is simply not rendered (the section's own
                         top-level header + the orange note already label the control)
                       - lab-report-form: no label ever existed here; only its placeholder drops "Other…"
```

No sequence diagram needed beyond this — there is no new async call, no new state transition. The mechanism is a conditional binding (label/header presence), not a structural rewrite of either branch's data flow.

## 12. Design Decisions (ADRs)

### `OTV-DD-1` — Conditional label/header binding in place, rather than a static relabel or a new shared component

- **Context:** The empty-ToC branch already renders the correct data (full catalog) via an existing, working control — only its label/header framing is wrong per Ángel's ticket. `lab-report-form` is additionally missing the branch entirely. **Revised after Judgment Day round 1** (`judgment.md`): a *static* relabel (the original plan) does not work because, in `rd-contributors-and-partners` and `aow-hlo-create-modal`'s Centers case, the same element serves both the auto-activated empty-ToC case and the genuine user-opted-in "Other(s)" case (confirmed by both judges as C-1's mechanism, and independently flagged by Judge A as SP-1's `OTV-AC-7` regression risk) — and a static relabel would also have left a pre-existing field-header duplicated on screen (C-1).
- **Decision:** Bind the label (Centers, both components) or the header's rendering condition (aow Science, which uses a separate `app-pr-field-header` + `app-pr-filter-multiselect` rather than a labeled multi-select — C-2) to `hasReferenceCenters()`/`hasReferenceScience()`, so the "Other(s)…" text survives for the genuine opt-in case and disappears only for the true empty-ToC auto-activated case. Remove the redundant field-header that duplicated the dropdown's own label in the two components' `@else` branches. Copy the branch shape (computeds + `@if`/`@else`) into `lab-report-form`, but keep that component's existing no-label convention — only its `placeholder` becomes conditional, per Judge B's finding (W3) that adding a `label` there would reverse a documented design decision (`lab-report-form/CLAUDE.md`: "No pasar `selectedLabel`… que el diseño no tiene").
- **Alternatives considered:**
  1. Extract a shared `<app-contributing-centers-picker>` section component used by all three call sites — cleaner long-term (matches `docs/ux-ui/design.md` DD-5's "shared section components" principle and would end the copy-paste drift each component's own `CLAUDE.md` already flags), but changes the save-wiring surface (`onSaveSection` / `buildCreateResultPayload`) in three places and is a materially larger diff than this bug warrants. Recorded as a follow-up (§13), not adopted here.
  2. Leave `lab-report-form` as-is (only fix the two components with the wrong label) — rejected because it leaves the ticket's own scope (three W1/W2 result-creation surfaces) inconsistent, and `lab-report-form`'s gap is the *same* root cause, just manifesting as "missing" instead of "mislabeled."
  3. (Rejected after Judgment Day) Static relabel of the existing element, as originally drafted — rejected because it breaks the non-empty-ToC opt-in case (`OTV-AC-7`) and leaves a duplicated header on screen (C-1). Superseded by the conditional-binding decision above.
- **Consequences:** Three near-identical template edits instead of one shared change — the drift these components already document (`lab-report-form/CLAUDE.md`: "Copia input-driven de `aow-hlo-create-modal`") persists one more cycle. Each touched component's `CLAUDE.md` `Verified:` stamp must be re-stamped in the same commit per the repo's `docs/COMPONENT-DOCS.md` convention — for two of the three folders (`rd-contributors-and-partners/CLAUDE.md`, `lab-report-form/CLAUDE.md`; the `aow-hlo-table-create-modal/` folder has no `CLAUDE.md` of its own, only the parent `entity-aow/CLAUDE.md` if that references this component — verify at task time).
- **Reversion challenge (Step 2.3), re-run post-correction:** With the conditional-binding fix, no shipped behavior is inverted for the non-empty-ToC path (`OTV-AC-7` now holds by construction — the "Other(s)…" text is preserved exactly when `hasReferenceCenters()`/`hasReferenceScience()` is `true`). The one still-real reversion is the **label text itself in the empty-ToC case**, asserted verbatim by an existing test: `rd-contributors-and-partners.zoneless.spec.ts:174` selects `app-pr-multi-select[label="Other(s) Contributing CGIAR Centers"]`, and that test specifically targets the empty-ToC auto-activated scenario (confirmed by reading the test — its own comment says so). **That selector MUST be updated to the new empty-case label as part of the same task that changes the binding** (see §10) — no collision with the existing `dropdown1()` helper in the same spec file, since the two target mutually-exclusive DOM states. No other shipped behavior (selectable values, save payload, a11y wiring beyond what §6.3 scopes) is broken by this change.

### `OTV-DD-2` — Default replacement label reuses the primary field's own label, per-component (not forced to a single cross-component string)

- **Context:** `requirements.md` `OTV-OQ-1` left the exact replacement string open. Judgment Day (W-A, confirmed by both judges) found that the three components' *primary* field labels for Science already differ verbatim today — `"Contributing Science Program/Accelerator"` (rd), `"Contributing Science Programs/Accelerators"` (aow), `"Contributing Science Programs"` (lab) — so a single universal replacement string across all three was never achievable without also rewriting each component's already-shipped primary label, which is out of scope (`requirements.md` §3 Out of scope).
- **Decision:** Each auto-activated empty-ToC control reuses **its own component's own existing primary-field label** (or, for `lab-report-form`, its existing `<p>` heading text) — not a single string forced across all three. `requirements.md`'s "Consistency" NFR is satisfied as: *within* each component, the empty-state framing now matches that component's own primary framing (no "Other(s)" text where there's nothing to be "other" than); it does **not** mean the three components' Science label now read identically to each other, since they didn't before this fix either and unifying them is out of scope.
- **Alternatives considered:** A distinct fourth label invented for the empty case (e.g. "Select CGIAR Centers") — rejected as unnecessary invention; reusing each component's own primary label is the most literal reading of Ángel's request ("un desplegable normal") and needs no new copy review, and keeps this fix from silently expanding into a copy-unification pass across three components.
- **Consequences:** If QA/Ángel wants the three components' Science labels unified during review, that is a separate, explicitly out-of-scope follow-up (three pre-existing primary-label strings would need to change, not just the empty-state ones) — not blocking this fix.

## 13. Open Gaps & Follow-ups

- **Follow-up (not this spec):** extract a shared "Contributing Centers/Science Programs, ToC-split" section component used by all three call sites, ending the three-way copy-paste drift each component's `CLAUDE.md` already documents (`OTV-DD-1` Alternative 1).
- **Accepted risk, NOT fixed in this pass (Judgment Day SP-2, single-judge finding — recorded as a known gap rather than folded into scope):** `lab-report-form`'s `tocCenters()`/`tocSciencePrograms()` populate asynchronously (`.then()` / `subscribe()`), and `resetForm()` does not clear them between re-arms. Until the async data lands, the new `hasReferenceCenters()`/`hasReferenceScience()` are transiently `false`, so the auto-activated dropdown can render on first paint even for an indicator whose ToC data does exist. If a user interacts with the "Other" picker in that narrow window before the async resolution flips the computed back to `true`, the second dropdown unmounts but nothing clears `otherCentersSelected()`/`otherScienceSelected()` — those values would still flow into the save payload. `rd-contributors-and-partners` has explicit reconciliation effects (`preselectCentersEffect`, `preselectScienceEffect`) for exactly this kind of drift; `lab-report-form` has none, and adding one is a genuine logic change beyond this Lite bug fix's scope. **Decision:** ship without a fix for this race; treat as an accepted risk. Revisit if it is ever observed in practice (it is timing-dependent — reachable only in the gap between first paint and the two async catalog fetches resolving — and no existing test demonstrates it as reliably reproducible today).
- **Risk:** `lab-report-form.component.ts` CLAUDE.md flags `optionValue` as load-bearing for `app-pr-multi-select` identity (`code` for centers, `id` for science programs) — since no new dropdown is created (the existing one is only re-gated, per the corrected §6.2), this risk is largely moot; `optionValue` is already set correctly on the existing controls. Recorded for completeness, not because the fix touches it.
- **Risk:** the Jest snapshot at `aow-hlo-table-create-modal/__snapshots__/aow-hlo-create-modal.component.spec.ts.snap` will need regeneration and manual review (not blind `-u`) to confirm only the intended label/header text changed.
