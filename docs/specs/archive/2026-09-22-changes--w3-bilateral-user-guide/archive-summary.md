## Historical notes

- **The read-only guard fired on production exactly as designed**, and the spec had pre-declared that path as a Pivot rather than an allowlist widening. `## Pivot Record: BG-T-7` carries two operator-approved amendments; no attempt was consumed, because a Pivot stops the loop rather than spending attempts on a spec that needs amending.
- **Three defect classes cost the most rounds, and none of them has a gate.** Seven content defects in `BG-T-11` (three caused by the Leader's own brief), three in `BG-T-10`, two more in `BG-T-13`'s HITL pass — all of them D8/D9: prose that was plausible, grammatical, and false.
- **The section list existed in four places and three of them shipped ungated.** `assemble.ts`'s `SECTIONS` and `verify-structure.ts`'s `EXPECTED_SECTIONS` were both stale W1/W2 tables; the TOC's anchors and labels were a third mirror; the TOC numerals a fourth. All four are now gated, the last two **derived** rather than tabulated.
- **Two provider rate-limit deaths** were handled as runtime events, not FAILs, consuming no attempts — recovered by the ladder's rung 4 (fresh worker auditing the partial diff) after model rotation.
- **CLARISA looked dead and was not.** `clarisa.cgiar.org/landing-page/glossary` returns 404 — the same SPA deep-link pattern already diagnosed on `reporting.cgiar.org`. The API answers 200 with 81 terms. A first query using the wrong field name nearly reported the source dead a second time.
