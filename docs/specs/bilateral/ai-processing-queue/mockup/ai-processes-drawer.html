Decisions shown. Grouping Running → Waiting → Finished puts the thing the user is waiting for first. Every waiting card says why it is waiting (your own job vs. a free lane) and shows a position, never an ETA; the spike showed the same document taking 115–183 s. Running cards show the stage from the server and the per-mix expected range (APF-R-6 D). The progress is indeterminate on purpose: no invented percentages (APF D4). Other users appear only as a count. The header trigger sits under the open drawer here; the drawer’s close button (and Esc) returns focus to it; see its states in §2. The drawer is role="dialog", traps focus, closes with Esc, returns focus to the trigger, and announces state changes through aria-live.
