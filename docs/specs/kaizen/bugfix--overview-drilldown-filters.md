## Lessons

### KZ-ODF-1 (Product) — Context-specific dashboard widgets must explicitly bind their scope dimensions in deep-link payloads
- **Root cause:** Overview cards representing distinct funding universes ("W1/W2 Reporting Status", "W1/W2 results by category and status") constructed drilldown links specifying only status or category, omitting `origin: 'W1/W2'`. Because the Results list contains both W1/W2 and W3/Bilateral records, arriving without an origin filter allowed bilateral records in the same status to contaminate the drilldown list (e.g. showing 23 results instead of the card's 12).
- **Evidence:** User reproduction on SP04: clicking "12 In progress" on W1/W2 card displayed 23 results. `dashboard-lab.component.ts:1491` link factory omitted `origin`.
- **Standardize (pending, spec branch):** Add guidance in `dashboard-lab/CLAUDE.md`: "Every drilldown link generated by an overview widget MUST explicitly stamp all partitioning dimensions (funding source/origin, effective phase, category, status, center) so the destination list view renders the exact population of the originating figure."
